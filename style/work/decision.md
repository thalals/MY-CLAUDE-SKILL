# 결정 위임·확인

> 읽는 때: 계획을 세우거나 선택지를 묻거나 방향이 정해진 뒤 이어서 작업할 때. 색인은 `index.md`.

## 하지 말아야 할 것

### 방향 확정 후 세부·미답 질문은 보수적 기본값으로 진행 — 2차 AskUserQuestion 모달 금지 (2026-07-10, 보강 5 · 최근 11-03, 병합 1 · 최근 11-04)
- 남은 세부가 ① 비파괴적·보수적 기본값이 명확하고 ② 틀려도 additive 복구 가능하면 모달 없이 진행 + "X 로 진행함, 다르면 알려달라" 한 줄 명시. 파괴적/비가역 결정만 짧은 텍스트로 기본값+대안 제시. 모달은 작업 시작 전 방향 미정 fork 에만 ("티켓 모호성 옵션 표" 룰과 상호 보완)
- 미답 질문의 기본값 = 유지·제외·보수 — 물은 질문에 직접 답이 없으면(다른 질문에만 답한 것은 승인 아님) 기존 분기·동작 제거는 유지, 인접 경로 포함은 제외, 남은 세부는 위 ①②를 갖춘 기본값. 구현·완료 보고 표에 끼워 넣지 않고, 포함이 필요해 보이면 제외한 채 보고 끝에 한 줄 재질문
- 짧은 한 줄로 답할 사안(네이밍 후보, 표현 방식)과 사용자가 이미 의견을 낸 사안은 모달 대상이 아니다 — 텍스트로 후보 2~3개 + 추천 근거만. 사용자가 직접 코드를 편집 중일 땐 특히 흐름을 끊는다
- 티켓 계획: 지목된 케이스 외 형제 케이스(같은 전이의 다른 사유)는 "범위 밖이라 기존대로, 필요하면 알려달라" 한 줄로 제외하고 기존 경로와 충돌하지 않는 근거를 '확인한 상호작용' 2줄로 붙인다 — 형제 케이스 포함을 선택지로 묻지 않는다
- 여러 티켓을 묶은 계획은 결정 사항을 번호로 모아 묻되 표마다 추천안을 표시해 두면 "오케이" 한 마디가 추천안 전부의 수락이다 — 번호별로 다시 묻지 않는다. 이력을 주지 않는 외부 API 의 상태 전이는 현재 상태 분포 실측으로 '추정' 표시 + 확정 조건 한 줄을 붙인다
- **왜:** 방향 확정 후 재확인 모달은 결정 가치가 낮고 라운드트립만 늘린다

## 더 신경써야 할 것

### 질문 전에 데이터로 자명한 부분과 결정 필요 부분 구분 (2026-06-25)
- 데이터 구조를 먼저 분석해 직접 계산/처리되는 부분은 단정으로 제시하고, 데이터가 없어 정책 결정이 필요한 부분만 질문
- **왜:** 자명한 부분까지 질문에 묶으면 "그건 데이터에 있잖아" 라운드트립이 는다

## 잘한 것 / 유지할 것

### 실행 전 영향·근거 제시 — 큰 변경은 옵션 표, 단순 실행도 근거 요약 (2026-05-04, 보강 3 · 최근 11-05)
- 영향 큰 작업 전 ①영향 파일/모듈 ②옵션 (A)/(B)/(C) ③장단점·마이그레이션 비용 ④추천안 표시 ⑤결정 후 즉시 적용
- 단순 명령형 요청도 의사결정이 포함되면 실행 전에 영향 위치·결정 근거 1-2줄·다른 정책과의 일관성을 짧게 제시 후 진행. 자명한 작업은 생략
- 순서·경합 리스크 질문("걱정 안 해도 되나")은 첫 줄 판정 → '순서 × 수신측 동작 × 결과' 표(코드 위치) → 뒤집히는 조건 → 방안 표 순. 방안 표에는 가장 단순한 동기 호출 안(선행 작업을 REST 로 끝낸 뒤 발행)을 반드시 넣는다 — 정교한 안만 올리면 사용자가 표 밖의 단순안으로 간다 (11-02, `code/kafka-dynamodb.md` "선후 의존" 룰)
- 사용자가 낸 구조 변경 제안도 바로 옮기지 않고 같은 형식으로 올린다 — 바뀔 모습(트리) + 좋아지는 점·실측 이전 비용(옮길 문서·고칠 링크 수)·앞서 합의한 원칙에 생기는 예외를 표로, 결정은 번호별 추천으로. 같은 원칙을 인접 범위로 넓히는 건 첫 결과를 본 뒤 따로 정하는 안을 추천한다
- **왜:** 결정 권한을 보존하면서 한 라운드트립에 의사결정과 실행이 같이 끝난다

### 티켓 모호성은 작업 시작 전 옵션 표로 결정 위임 (2026-06-12)
- ①제목 vs 본문 충돌 ②본문 내 모순 ③명시되지 않은 인접 영역 — 발견 시 충돌 위치 표 + 옵션 2-4개(추천 라벨 X)로 결정 받고 시작. 자동 해석 후 진행 금지
- **왜:** 티켓은 작성 시점 의도와 다를 수 있다 — 1회 라운드트립이 재작업보다 싸다
