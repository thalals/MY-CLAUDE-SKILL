# 스타일 색인

> 세션을 시작할 때 이 파일만 읽는다. 주제 파일은 지금 하는 작업에 맞는 것만 읽는다.

## 읽는 법

1. 아래 '작업별 최소 세트' 에서 지금 작업의 행을 찾아 '반드시' 칸의 파일을 작업 전에 읽는다. '해당하면' 칸은 조건이 맞는 것만 읽는다.
2. 여러 행에 걸치면 각 행의 '반드시' 를 모두 읽는다. 이미 읽은 파일은 다시 읽지 않는다.
3. 작업 종류가 바뀌면(구현 → 보고, 코드 → 문서) 그때 그 행의 파일을 읽는다.
4. **어느 행인지 애매하거나 표에 없는 작업이면 추측하지 말고 작업 전에 사용자에게 묻는다.** 읽을 후보 파일과 추천을 한 줄로 내고 답을 받은 뒤 시작한다.
5. 규칙 하나만 필요하면 '파일 목록' 의 제목으로 `grep -n "^### <제목 앞부분>"` 을 하고 그 항목만 읽는다. 다른 규칙이 `"제목" 항목` 으로 가리킬 때도 같다.
6. 규칙을 더하거나 고치는 일은 `collect-feedback` 스킬로만 한다. 옛 통합 파일(`code_style.md` 등)은 `style-archive/` 로 옮겼고 읽지 않는다.

## 작업별 최소 세트

| 작업 | 반드시 | 해당하면 |
|---|---|---|
| 질문에 답하기, 코드·기록 조회 | 없음(아래 우선순위만) | 답이 길거나 선택지·리스크를 다루면 work/reporting |
| 티켓·여러 단계 작업 시작, 계획·선택지 제시 | work/process, work/decision | 아래 코드 행 |

| 버그 원인 분석, 시그니처·타입 변경 영향 확인 | work/verification | — |

## 우선순위 — 작업 방식 (2026-09-02 산정, 11-04 6·7위 교체, 11-10 압축 보정·1·2위 교체, 11-10 주제 파일로 분리, 11-11 3·4위 교체)

> 사용자가 자주 반복한 피드백 테마다. 규칙이 충돌하거나 주의를 배분할 때 위 순위부터 지킨다.
> 표기: (룰 n · 보강 m · 최근 MM월). 순위 근거는 룰 수 + 보강 횟수이고 수치는 collect-feedback 이 갱신한다.

1. **결정 권한 보존과 확인의 균형** (룰 11 · 보강 22 · 최근 11월) — 모호·파괴적·중복의미 결정은 옵션 표로 위임하고, 방향이 정해진 뒤에는 재확인 없이 보수적 기본값으로 진행
2. **측정·증거 우선, 추측 금지** (룰 7 · 보강 21 · 최근 11월) — 단정 전에 실측·프로브·원문 인용. 가설은 검증 수단·해석 분기와 함께 제시
3. **구조화 답변 — 표·갈라 답하기** (룰 6 · 보강 15 · 최근 11월) — 표/단계 구조로 보고, 리스크는 조건·메커니즘·범위·코드 위치로, 부분만 맞는 지적은 맞는/아닌 쪽을 갈라 답변
4. **요청 범위 준수 — 과잉 대응 금지** (룰 6 · 보강 17 · 최근 11월) — 지정 범위만 수정, 범위 밖 개선은 별도 제안으로
5. **전수 영향 분석** (룰 3 · 보강 4 · 최근 10월) — 변경·수정 시 같은 개념/패턴의 형제 지점을 grep 전수 점검
6. **사용자 표현 그대로 수용** (룰 3 · 보강 5 · 최근 11월) — 표면 의미 우선, 임의 추상화·재구성 금지
7. **기존 적용·레퍼런스 복제 금지** (룰 3 · 보강 4 · 최근 11월) — 현재 컨텍스트의 데이터 구조에서 도출 (구현 계열은 코드 테마 참조)

## 우선순위 — 코드 (2026-09-02 산정, 10-28 재산정, 11-02 1·2위 교체, 11-04 3·4위 교체, 11-10 압축 확인, 11-10 주제 파일로 분리)

1. **과잉 설계 금지 — 최소 구조 유지** (룰 9 · 보강 30 · 최근 11월) — 재사용이 실재할 때만 추출/분리/신설, 아니면 인라인·기존 레이어에. 보호할 로직 없는 테스트도 신설 금지
2. **네이밍은 도메인 의미·기존 패턴 기준** (룰 11 · 보강 20 · 최근 11월) — 사용자가 가장 자주 직접 정정한 영역. 첫 명명부터 기존 패턴 grep + 도메인 용어 확인, 애매하면 질문
3. **silent fail 금지 — fail-fast·명시 거부** (룰 7 · 보강 13 · 최근 11월) — 불확실한 값은 채우지 않고, 도달 불가 분기·필수 부재·비정상 입력은 식별자 포함 예외로
4. **데이터 응집 — 로직은 데이터/소비자가 있는 곳에** (룰 6 · 보강 11 · 최근 11월) — 판단·색인·술어는 소유 객체 내부에. 입력·결과 양쪽이 데이터를 가지면 판정 결과의 소비자가 위치 기준
5. **기존 것 재사용 우선** (룰 3 · 보강 8 · 최근 11월) — 새 const/VO/파서/조회를 만들기 전에 같은 도메인 grep
6. **현재 데이터 구조에서 도출 — 리팩토링 잔재 정리** (룰 3 · 보강 5 · 최근 11월) — 레퍼런스 복사 대신 구조 분석, 방식 변경 시 dead 요소 점검
