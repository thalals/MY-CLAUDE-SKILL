# research-efficiency

대화가 참고하는 지시와 반복 절차의 효율을 연구하는 연구실이다. 효율은 품질(지시가 지켜지고 기록이 맞는 것)을 지키면서 드는 토큰과 값을 줄이는 것이다.

연구는 회차를 넘어 쌓인다. 회차는 이 스킬을 한 번 불러서 하는 연구다. 회차마다 지난 회차들이 장부에 쌓은 것에서 시작하고, 이번에 알게 된 것을 다음 회차가 찾아 쓸 자리에 쌓고 닫는다. 장부에 쌓지 않은 연구는 다음 회차에 없는 것과 같다. 닫기 전에는 방향과 기록과 이 스킬 자체가 지금도 맞는지 검증하고 고친다. 연구실도 연구 대상이다.

새 세션에서 부른다. 대화 내용이 필요 없고, 무거운 대화에서 부르면 연구가 비싸진다(F-03). 한 회차는 초점 하나만 다룬다.

이 회차의 세션 ID 는 `${CLAUDE_SESSION_ID}` 다. 닫을 때 쓴다. 중괄호가 글자 그대로 보이면 스킬이 불린 것이 아니므로 `--session` 없이 닫는다(도구가 가장 최근에 바뀐 세션을 쓴다).

## 연구 대상

항목마다 아래 갈래 가운데 하나를 단다.

- 맥락: 늘 실리는 맥락. 세션 첫 호출에 실리는 CLAUDE.md, 메모리 색인, 스킬 목록, 훅이 넣는 글, 커넥터 안내, 도구 정의. 모든 호출이 다시 읽는다.
- 지시: 필요할 때 읽는 지시. 스타일 색인과 주제 파일, 스킬 본문과 reference, 볼트 규칙 파일과 지도. 읽은 뒤의 모든 호출이 다시 읽는다.
- 절차: 반복 절차. record-obsidian, collect-feedback, collect-worklog, jira 같은 스킬의 한 번 실행.
- 효과: 지시가 실제로 지켜졌는가. 실행 뒤 사용자가 고쳐 달라고 한 횟수, 같은 피드백이 다시 나온 횟수, lint 결과, 평가 시나리오.
- 측정: 재는 법과 이 도구.
- 연구실: 이 연구실을 운영하는 법.

## 장부

`<스킬>/research/` 에 있다. `<스킬>` 은 이 스킬의 Base directory 다.

| 자리 | 담는 것 | 쓰는 쪽 |
|---|---|---|
| `knowledge.md` | 종합. 지금 아는 것을 근거 번호와 함께 80줄 안에 적는다. 회차를 시작할 때 읽는 글은 이것뿐이다 | 회차 |
| `findings/F-번호.md` | 사실 하나. 재서 확인한 것, 다시 낼 수 있는 근거, 한계, 다시 볼 때 | 회차 |
| `directions/D-번호.md` | 방향 하나. 아직 확인하지 않은 가설이나 할 수 있는 개선 | 회차 |
| `attempts/A-번호.md` | 시도 하나. 실제로 바꾼 것과 미리 적은 예측, 판정 기준 | 회차 |
| `log.tsv` | 회차 기록. 초점, 한 일, 배운 것, 다음에 할 일, 든 값 | 도구(`close`) |
| `index.md` | 모든 항목의 한 줄 목록 | 도구 |
| `runs.tsv`, `base.tsv` | 측정값 | 도구(`--save`) |

- 항목 형식, 상태 말, 고치는 규칙, 점검 번호는 `<스킬>/reference/ledger.md` 에 있다. 항목을 쓰거나 고치기 전에 읽는다.
- 지표 정의, 실행 구간, 품질 신호, 알려진 함정은 `<스킬>/reference/metrics.md` 에 있다. 수치를 해석하기 전에 읽는다.
- 번호(F-, D-, A-)는 한 번 붙이면 바꾸지 않는다. 틀린 사실, 실패한 시도, 기각한 방향도 지우지 않는다. 다음 회차가 같은 길을 다시 가지 않게 하는 기록이다.

## 도구

`python3 -B <스킬>/scripts/efficiency.py <명령>` 으로 돌린다. 숫자는 이 도구 출력에서 나온 값만 쓰고, 곱하거나 나눈 값은 식을 함께 적는다. 세션 ID 와 서브에이전트 ID 는 앞 8자로 준다.

장부를 다루는 명령
- `status`: 회차 시작. 쌓인 것, 지난 회차의 인계, 판정 대기 시도의 진행, 열린 방향, 다시 볼 사실, 환경 변화, 연구실 성적, 종합을 낸다.
- `find 말 ...`: 선행 연구 찾기. 모든 말이 들어 있는 항목과 종합·회차 기록의 줄을 낸다. `--kind F|D|A` 로 좁힌다.
- `show 번호 ...`: 항목 본문과 그 번호를 인용한 곳. `show --open D` 는 열린 방향 전부다.
- `new F|D|A --title 제목`: 다음 번호로 항목 파일을 만든다.
- `set 번호 라벨 값`: 라벨 한 줄을 바꾸거나 더한다. 상태, 우선, 확인 날짜를 고칠 때 쓴다. 빈칸이 든 라벨은 따옴표로 감싼다.
- `lint`: 장부 점검. 차단(E)은 고쳐야 닫을 수 있다. 보고(R) 가운데 R2 와 R11 은 7단계에서, 나머지는 종합 회차에서 정리한다.
- `close ...`: 회차 닫기. 점검하고, 목록을 다시 쓰고, 이 회차에 든 값을 재서 7단계의 답과 함께 회차 기록에 적는다.

재는 명령
- `runs --days N --save`: 스킬 실행을 재서 runs.tsv 에 옮긴다. 다시 잰 줄은 새 값으로 바뀐다. `runs --session ID --skill 이름` 은 한 세션의 실행을 자세히 낸다.
- `stats --skill 이름 --since 날짜 --until 날짜`: runs.tsv 의 구간별 중앙값. 바꾸기 전후를 견줄 때 쓴다. `--model`, `--ctx-below`, `--ctx-above`, `--session`, `--not-session` 으로 조건이 비슷한 실행만 고른다. 멈춘 실행이나 요청 종류가 다른 실행 하나는 `--not-run "YYYY-MM-DD HH:MM"` 으로 시작 시각을 줘서 뺀다. 끝에 기준 단가 구성(본 대화와 서브, 서브 안의 캐시 읽기·쓰기·출력)과 서브에이전트가 맥락을 캐시에 다시 쓴 실행을 낸다.
- `trend --skill 이름`: 달마다(`--by week` 는 주마다)의 추이. 쌓인 측정으로 나아지는지 본다.
- `carry --session ID --skill 이름` (서브에이전트는 `--agent ID`): 한 실행에서 맥락에 들어온 것과 그것을 다시 읽은 값. 어디를 줄일지 찾을 때 쓴다. `--list` 는 호출을 차례대로 낸다(맥락, 출력, 도구).
- `after --session ID --skill 이름`: 실행 뒤의 사용자 발언. 정정 요청 수를 세는 품질 확인에 쓴다.
- `base --project 이름일부 --save`: 새 세션 첫 호출의 크기와 구성. `base --list` 는 세션별 추이다.
- `reads --days N`: 지시 파일을 참조한 횟수와 스킬 호출 횟수.
- `total --session ID`: 세션 전체에서 본 대화와 서브에이전트가 쓴 것.
- `check --session ID`: 하니스 자체 집계와 이 도구 합계의 차이. 도구를 고친 뒤와 환경이 바뀐 뒤에 쓴다.

## 회차

1. 시작한다. 이 글 끝의 '지금 연구실' 이 `status` 의 출력이다. 비어 있거나 명령이 글자 그대로 보이면 `status` 를 직접 돌린다. 현황과 종합이 이번 회차의 출발점이다. 다른 장부 파일은 필요해질 때 `find` 와 `show` 로 읽고, 항목 폴더를 통째로 읽지 않는다.
2. 옮긴다. `status` 가 알려 준 `runs --days N --save` 로 지난 회차 뒤의 실행을 장부에 옮긴다. 세션 원본은 30일 뒤 지워지므로(F-13) 초점이 무엇이든 이 단계는 한다. 환경 변화가 보이면 `check` 부터 하고, 늘 실리는 맥락이 바뀌었을 만하면 `base --project 이름일부 --save` 를 한다.
3. 초점을 하나 정한다. 순서는 사용자가 준 것, 횟수가 찬 판정 대기 시도, 감시에서 나빠진 시도, 우선이 가장 높은 열린 방향, 권고가 뜬 종합이다. 나머지는 '다음에 할 일' 로 넘긴다.
4. 선행 연구를 확인한다. 초점의 핵심어(스킬 이름, 지표, 대상)로 `find` 를 하고 걸린 번호를 `show` 로 읽는다. 이미 잰 것은 다시 재지 않고 그 값에서 시작한다. 다시 재는 것은 그 사실의 '다시 볼 때' 에 걸리거나 조건이 다를 때뿐이다. 틀린 사실, 실패한 시도, 기각한 방향도 선행 연구다. 이번에 쓰는 항목의 근거에 선행 번호를 적고, 없으면 '선행 없음' 과 찾아본 말을 적는다.
5. 연구한다.
   - 판정: 판정 대기 시도의 '틀렸다고 볼 기준' 을 `stats` 의 전후 값과 견준다. 모델이 다른 실행끼리는 기준 단가 환산과 누적 입력으로 견주고, 시작 맥락이 비슷한 실행은 `--ctx-below`, `--ctx-above` 로 따로 본다. 필요한 횟수와 합격 폭은 미리 적힌 대로 한다. 품질 확인 줄은 `after` 로 채운다. 횟수가 모자라거나 품질 확인이 비어 있으면 측정 대기로 둔다. 판정하면 결론과 예측 평가(맞음이나 빗나감, 그 까닭)를 적는다. 실패한 변경을 되돌릴지는 사용자가 정한다.
   - 탐색: '먼저 잰다' 방향이나 사용자의 질문을 잰다. 큰 항목부터 본다. 스킬은 `stats` 의 합과 중앙값, 실행 안은 `carry` 의 큰 단계, 늘 실리는 맥락은 `base` 의 큰 구성 요소다. 재서 예상과 기준을 채우면 후보로 올리고, 잰 이득이 작으면 수치를 대고 기각한다. 물음에 답하는 것이 목적이었으면 완료로 닫는다. 예상은 토큰과 기준 단가 환산 둘 다로 적는다. 방법이 Claude Code 기능에 달려 있으면 공식 문서 원문으로 확인한다.
   - 적용: 사용자가 고른 방향을 시도로 올린다. 바꾸기 전에 `new A` 로 사전 측정, 예측, 틀렸다고 볼 기준(필요 횟수와 합격 폭), 품질 확인 방법을 먼저 적는다. 예측은 숫자로 쓰고 종합의 어느 문장에서 나왔는지 번호를 단다. 사후 측정은 실제 사용이 쌓인 뒤의 회차에서 한다. 같은 때에 다른 것도 바뀌면 겹친 변경에 적는다.
   - 종합: 아래 '종합 회차' 를 따른다.
6. 쌓는다.
   - 사실: 알게 된 것마다 `new F` 로 하나씩 쓴다. 이미 있는 사실이 더 굳어졌으면 새로 만들지 않고 그 사실의 근거, 세기, 확인 날짜를 고친다. 틀린 것으로 드러난 사실은 정정 줄을 더하거나 상태를 바꾼다.
   - 방향: 상태를 `set` 으로 고친다. 닫을 때(채택, 기각, 완료)는 결과 줄에 잰 값과 까닭, 나온 사실 번호를 적는다. 새로 떠오른 가설은 `new D` 로 올린다.
   - 종합: 믿음이 생기거나 바뀌었으면 `knowledge.md` 의 그 문장을 고친다. 빗나간 예측과 그 까닭은 '통하지 않은 것과 빗나간 예측' 에 적고, 답을 얻은 물음은 '아직 모르는 것' 에서 지운다. 판정이 끝나지 않은 수치는 종합에 쓰지 않는다.
7. 검증하고 발전시킨다. 닫기 전에 이번 회차에서 겪은 것을 근거로 방향, 기록, 이 스킬이 지금도 맞는지 확인하고, 고칠 수 있는 것은 이 자리에서 고친다. `lint` 와 `status --brief` 를 다시 돌려서 보고 아래 셋에 답한다. 답에는 본 것(번호, 명령, 수치)과 고친 것을 적고, 고칠 것이 없으면 본 것만 적는다. 이 답이 닫을 때의 `--check-directions`, `--check-records`, `--check-skill` 이다.
   - 방향이 유효한가: 열린 방향 가운데 이번에 알게 된 사실이나 유효하지 않게 된 사실(`lint` 의 R11) 때문에 근거를 잃은 것, 답이 이미 나온 것이 있는가. 우선이 높은 방향이 지금 값이 가장 큰 곳(`status` 의 스킬별 값, 판정 대기 시도)을 가리키는가. 근거를 잃은 방향은 근거를 고치거나 보류, 기각으로 닫고, 답이 나온 방향은 완료로 닫는다. 우선을 바꿔야 하면 보고에서 제안한다.
   - 기록이 유효한가: 이번에 쓴 항목의 수치마다 근거에 도구 명령이 있고 횟수와 조건이 붙었는가. 시작 현황, 종합, `find` 로 필요한 선행 연구를 찾았는가. 찾지 못해 다시 잰 것, 틀린 것으로 드러난 사실, 유효하지 않은 사실에 기댄 종합 문장(`lint` 의 R2), 이번에 기댄 사실 가운데 '다시 볼 때' 에 걸린 것을 고친다(정정 줄, 상태, 종합 문장).
   - 이 스킬이 유효한가: 본문의 지시나 도구가 이번 일을 막거나 헛돌게 한 곳이 있는가. 본문과 도구가 어긋난 곳, 임시 스크립트로 낸 값, 쓰지 않은 단계, 빠진 단계를 본다. `status` 의 연구실 성적으로 연구실이 든 값만큼 줄였는지도 본다. 도구와 reference 의 결함, 본문의 틀린 서술은 고치고 그 명령을 다시 돌려 확인한다. 회차 순서, 장부 형식, 규칙을 바꾸는 일은 고치지 않고 `new D`(갈래 연구실)로 올려 보고에서 사용자가 고르게 한다.
8. 닫는다. `close --kind 종류 --focus "초점" --did "한 일" --next "다음에 할 일" --ids "다룬 번호" --check-directions "방향의 답" --check-records "기록의 답" --check-skill "스킬의 답" --session ${CLAUDE_SESSION_ID}` 를 돌린다. 종류는 구축, 측정, 판정, 탐색, 적용, 종합 가운데 하나다. `--next` 는 아래 '보고' 의 다음 회차에 할 일과 같은 형식으로 쓴다. 차단이 나오면 고치고 다시 닫는다. 그 뒤 스킬 폴더를 iCloud `claude/skills/research-efficiency/` 에 복사하고 `bash "$HOME/Desktop/hmin/MY-CLAUDE-SKILL/.sync/sync.sh" -m "research-efficiency: <초점> <종류> 회차"` 를 돌린다(`-m` 은 커밋 제목).
9. 보고한다.

재기만 하는 날은 종류를 측정으로 닫고 1, 2, 8, 9만 한다.

## 종합 회차

`status` 가 권할 때(마지막 종합 뒤 5회차)와 사용자가 부를 때 한다.

1. `lint` 의 보고를 정리한다. 아무도 인용하지 않는 사실(R3)은 종합에 넣거나 그대로 둘 까닭을 본다. 오래된 사실(R4)은 다시 재서 확인 날짜를 고치거나 낡음으로 바꾼다. 열린 방향이 많으면(R5) 오래 손대지 않은 것을 보류나 기각으로 닫는다.
2. 종합을 다시 쓴다. 새 사실을 합치고, 겹치는 문장을 줄이고, 유효하지 않게 된 사실에 기댄 문장을 고친다.
3. 회차마다 7단계에서 적은 답(회차 기록의 learned)과 갈래가 연구실인 열린 방향을 모아 본다. 여러 회차에 되풀이된 것부터 고치고, 회차 순서나 장부 형식을 바꿔야 하면 사용자에게 제안한다.
4. 연구실 성적(든 값, 줄인 값, 예측 평가)과 `trend` 를 보고하고, 방향의 우선을 사용자와 다시 정한다.

## 누가 정하나

- 연구실이 스스로 한다: 재기, 사실 쓰기, '먼저 잰다' 방향을 재서 후보나 기각으로 옮기기, 근거를 잃은 방향 닫기, 종합 고치기, 도구와 reference 의 결함과 본문의 틀린 서술 고치기.
- 사용자가 정한다: 어느 방향을 시도할지, 방향의 우선, 실패한 변경을 되돌릴지, 지시·스킬·설정·규칙 파일을 바꾸는 일, 이 스킬의 회차 순서와 장부 형식.

## 바꾸는 길

- 스타일 규칙은 collect-feedback 으로만 고친다.
- 볼트 구조와 규칙, record-obsidian 은 사용자가 고른 것만 고친다. 그 대화에서 정하지 못한 채 끝나면 볼트 `proposals.md` 에 제안으로 남겨 다음 기록 보고가 다시 묻게 한다.
- 그 밖의 스킬, CLAUDE.md, 설정(플러그인, 커넥터, 훅)은 사용자가 고른 것만 고친다.
- 이 도구를 고치면 reference 와 위 도구 목록을 같은 편집에서 맞추고 `check` 로 합계를 다시 대조한다. 지표의 정의를 바꾸면 도구의 판(METRICS_VERSION)을 올린다.
- 이 스킬의 회차 순서나 장부 형식을 고치면 `<스킬>/evals/scenarios.md` 의 시나리오를 사본에서 다시 돌린다. 본문의 틀린 서술만 고쳤으면 고친 명령을 한 번 돌려 확인한다.

## 지키는 것

- 같은 도구, 같은 정의, 같은 판으로 잰 값끼리만 견준다. 예전 보고의 숫자는 도구로 다시 내서 쓴다.
- 한두 번 잰 값으로 줄었다고 쓰지 않는다. 횟수와 조건을 함께 적는다.
- 비용이 줄어도 품질 확인이 없으면 채택하지 않는다. 줄인 값이 작은데 구조가 복잡해지는 변경도 채택하지 않는다. 없애서 같거나 나아지면 채택한다.
- 예측은 재기 전에 적고, 잰 뒤에 고치지 않는다.
- 연구 자체의 비용도 잰다. `close` 가 회차마다 적고 `status` 가 더해서 낸다. 서브에이전트를 쓰면 그 몫도 들어간다.
- 도구가 내지 못하는 값을 임시 스크립트로 쟀으면 근거에 그렇게 적고, 다시 쓸 측정이면 도구의 명령으로 옮긴다.
- 장부에는 숫자와 식별자만 옮긴다. 도구 출력에 섞인 명령 설명, 대화 내용, 비밀값은 옮기지 않는다.
- 항목과 종합은 쓰기 직전에 다시 읽는다. 다른 세션이 고쳤을 수 있다.
- 본문과 종합은 고칠 문장만 고친다. 통째로 다시 쓰면 세부가 닳는다.
- 장부에 자리가 없는 내용은 새 종류의 파일을 만들지 않고 보고에서 구조 제안으로 올린다.
- 세션 원본은 읽기만 한다.

## 보고

- 초점과 결론: 무엇을 몇 번 쟀고 선행 연구의 어느 값과 얼마나 다른지.
- 새로 쌓은 것: 사실, 방향, 시도의 번호와 한 줄씩.
- 종합에서 바뀐 문장.
- 검증한 결과: 방향, 기록, 이 스킬에서 본 것과 고친 것, 올린 연구실 방향.
- 사용자가 정할 것: 추천 순서와 이유(예상 이득, 품질 위험, 드는 것).
- 확인하지 못한 것과 다음 회차에 할 일.
- 정할 것과 다음 회차에 할 일은 항목마다 하는 일 한 줄, 무엇을 개선하는 일인지(스킬, 스타일, 볼트, 늘 실리는 맥락, 연구실 가운데), 정할 것이 있으면 선택지와 추천으로 쓴다. 사실, 방향, 시도의 번호와 장부의 말(시도, 판정)은 그대로 쓰지 않고 하는 일로 풀어 쓰며, 번호는 괄호 참조로만 단다.
- 전체 흐름(개선 순환, 누가 정하나, 대상별로 바꾸는 길)은 보고에 다시 쓰지 않고 `<스킬>/README.md` 를 가리킨다.
