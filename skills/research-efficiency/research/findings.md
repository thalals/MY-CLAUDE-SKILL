# 확인한 사실

> 효율 연구에서 재서 확인한 사실만 둔다. 한 사실은 `## F-번호 제목` 하나이고 확인한 날, 근거(다시 낼 수 있는 명령과 그 값), 사실, 한계를 적는다. 틀린 것으로 드러나면 지우지 않고 `- 정정:` 줄을 더한다. 짐작과 아직 재지 않은 것은 directions.md 에 둔다. 명령은 `scripts/efficiency.py` 의 하위 명령이다.

## F-01 한 번의 실행이 읽는 토큰은 호출 수 × 그때의 맥락 크기다
- 확인: 2026-11-16
- 근거: `runs --session f4af52de --skill record-obsidian` → 호출 43, 맥락 159,319 → 최대 298,614, 누적 입력 10,409,607 (캐시 읽기 10,138,226 · 캐시 쓰기 271,295 · 안 실린 입력 86).
- 사실: 누적 입력의 97%(10,138,226 ÷ 10,409,607)가 캐시 읽기다. 읽은 파일의 크기가 아니라 호출 수와 그 시점의 맥락 크기가 누적 입력을 정한다.
- 한계: 토큰 수 기준이다. 값으로 치면 다르다(F-02).

## F-02 값으로 치면 캐시 쓰기와 출력이 절반을 넘는다
- 확인: 2026-11-16
- 근거: 같은 실행의 정가 환산 $5.18 = 캐시 읽기 $2.03 + 캐시 쓰기 $2.17 + 출력 $0.98. Opus 5.5 정가는 백만 토큰당 캐시 읽기 $0.20, 1시간 캐시 쓰기 $8, 출력 $20.
- 사실: 출력 단가는 캐시 읽기의 100배, 1시간 캐시 쓰기는 40배다. 호출 수를 줄여 읽기를 아껴도 새로 쓰는 내용과 생각 토큰이 늘면 값은 줄지 않는다.
- 한계: 정가 환산은 종류가 다른 토큰을 견주는 가중치다. 구독 한도가 종류별 토큰을 얼마로 치는지는 확인하지 못했다(D-10).
- 정정: 2026-11-16 아침 보고의 "비용은 호출 수 × 맥락 크기가 거의 다 정한다" 는 토큰 수 기준으로만 맞다.

## F-03 무거운 대화에서 시작하면 시작 맥락을 호출마다 다시 읽는 값이 크다
- 확인: 2026-11-17
- 근거 1: `carry --session f4af52de --skill record-obsidian` → 시작 맥락 159,319 × 43번 = 6,850,717 (누적 입력의 66%). `carry --session 071d0c00 --skill record-obsidian` → 829,512 × 44번 = 36,498,528 (92%).
- 근거 2: collect-worklog. `stats --skill collect-worklog --since 2026-08-24 --session 15589b2d` → 오래 쓴 한 세션 21번, 시작 맥락 중앙값 572,040, 누적 입력 중앙값 8,455,804, 정가 환산 중앙값 $10.55 (합 $255.22). 같은 명령에 `--not-session 15589b2d` → 새 세션 23번, 시작 맥락 중앙값 61,608, 누적 입력 중앙값 2,498,356, 정가 환산 중앙값 $2.57 (합 $74.02).
- 사실: 같은 스킬도 시작 맥락이 크면 몇 배가 든다. 값으로 치면 시작 맥락을 다시 읽은 몫은 11-16 실행에서 6,850,717 × $0.20/백만 = $1.37 로 그 실행 $5.18 의 26%, 11-12 실행에서 36,498,528 × $0.20/백만 = $7.30 으로 $15.88 의 46%다.
- 한계: carry 는 두 실행만 봤다. 근거 2의 두 묶음은 모델과 시기가 다르다(오래 쓴 세션은 모두 opus-4-8, 새 세션은 네 모델이 섞임). 날마다 워크로그 양도 다르다. 스킬 본문을 고치는 것보다 큰지는 재지 않았다(D-01).

## F-04 쉬었다가 이어 하면 첫 호출이 대화 전체를 캐시에 다시 쓴다
- 확인: 2026-11-17
- 근거: runs.tsv 의 first_write 열(`runs --session ID --skill record-obsidian` 의 '첫 호출 캐시 쓰기'). record-obsidian 옛 구조 16번 가운데 6번이 10만 이상이다. 11-12 는 802,193(시작 맥락 829,512), 11-11 16:30 은 494,447, 11-10 18:25 는 413,577, 11-13 은 345,911, 11-05 17:55 는 333,640, 11-16 은 132,000. 1시간 캐시 쓰기 정가($8/백만)를 곱하면 11-12 는 $6.42(그 실행 $15.88 의 40%), 11-13 은 $2.77($6.73 의 41%), 11-16 은 $1.06($5.18 의 20%).
- 사실: 캐시가 식은 뒤의 첫 호출은 그때 맥락의 대부분을 입력 단가의 2배로 다시 쓴다.
- 한계: 본 대화 캐시 수명 1시간은 원본의 쓰기 종류(1h)로 본 것이다. 얼마나 쉬면 식는지는 실행마다 재지 않았다.

## F-05 서브에이전트 완료 값(totalTokens)은 누적이 아니라 마지막 호출 한 번의 크기다
- 확인: 2026-11-16
- 근거: 한 서브에이전트의 totalTokens 57,676 = 마지막 호출의 안 실린 입력 3 + 캐시 쓰기 8,441 + 캐시 읽기 4,330 + 출력 44,902.
- 사실: 완료 알림이나 Agent 결과의 토큰 수를 더하면 비용이 아니라 마지막 맥락 크기의 합이 나온다.
- 한계: 근거의 한 건은 원본의 Agent 결과를 손으로 본 값이라 도구로 다시 낼 수 없다. 아래 정정 줄의 시나리오별 누적 입력은 `total --session f4af52de --top 16` 으로 다시 낸다.
- 정정: 2026-11-16 보고의 "평가 시나리오 A~D 에 108만 토큰" 은 이 값을 더한 것이었다. 누적 입력은 14,841,278 (A 5,793,808 · B 1,768,985 · C 5,902,089 · D 1,376,396), Sonnet 5.5 정가 환산 $9.31 이다.

## F-06 새 맥락의 서브에이전트도 작게 머물지 않는다
- 확인: 2026-11-16
- 근거: 평가 시나리오 A(계획만 세우는 시험, Sonnet 5.5) 는 호출 38, 맥락 42,775 → 272,994, 누적 입력 5,793,808, 출력 154,128 중 생각 130,602. `stats --skill collect-feedback` → 27번 모두 포크 실행, 호출 중앙값 18, 누적 입력 중앙값 1,653,339, 기준 단가 환산 중앙값 $1.57.
- 사실: 서브에이전트는 약 43,000~50,000 토큰에서 시작해 읽는 만큼 커진다. 캐시 쓰기는 5분 수명(입력 단가의 1.25배)이다. 출력의 대부분이 생각 토큰일 수 있다.
- 한계: 시나리오는 실제 기록이 아니다. 실제 기록의 서브에이전트는 A-01 의 사후 측정에서 본다.

## F-07 본 대화만 재면 서브에이전트가 쓴 것이 빠진다
- 확인: 2026-11-17
- 근거: `total --session f4af52de` (11-17 09:30 무렵) → 본 대화 호출 224, 누적 입력 76,561,869, 정가 환산 $70.89. 서브에이전트 16개 호출 344, 누적 입력 60,125,138, 출력 1,549,939(생각 1,329,436), 정가 환산 $48.86. 11-16 아침 측정은 본 대화만 쟀다.
- 사실: 일을 서브에이전트로 옮기면 본 대화 수치는 줄지만 합계는 따로 봐야 한다. `runs` 는 둘을 합쳐 낸다.
- 한계: 세션이 이어지는 동안 값이 커진다.

- 한계: 토큰은 글자당 0.38 한 비율로 어림했다. 한글이 많은 부분은 낮게 나온다(D-09). Claude Code 2.1.311 의 요청 기록 형식에 기댄다.

## F-10 스킬별 한 번 비용의 기준선

- 근거: `runs --days 45 --save` 뒤 `stats`. 실행 121번.
- 사실: 한 번의 기준 단가 환산 중앙값은 record-obsidian 옛 구조 $5.28, collect-worklog $3.96, jira 첫 턴 $3.85, collect-feedback $1.57 이다. 정가 환산은 쓴 모델에 따라 달라 jira 가 $7.82 로 가장 크다(30번 가운데 24번이 Fable 모델).
- record-obsidian 옛 구조: `stats --skill record-obsidian --until "2026-11-16 17:00"` → 16번(11-05~11-16), 누적 입력 중앙값 9,541,450 (671,689~39,596,254), 기준 단가 환산 중앙값 $5.28 (합 $101.51), 본 대화 호출 중앙값 27, 시작 맥락 중앙값 322,715. 같은 명령에 `--ctx-below 120000` → 시작 맥락 12만 아래 4번, 누적 입력 중앙값 5,302,537, 기준 단가 환산 중앙값 $2.77 (11-10 16:03 의 전체 최신화 28,417,374 포함).
- collect-feedback: `stats --skill collect-feedback` → 27번(08-26~11-16), 누적 입력 중앙값 1,653,339, 기준 단가 환산 중앙값 $1.57 (합 $49.34), 정가 환산 중앙값 $2.22 (합 $64.14).

## F-12 공식 문서의 근거 문장
- 확인: 2026-11-16 (code.claude.com/docs/en/costs, /skills, /statusline, platform.claude.com/docs/en/about-claude/pricing)
- 사실: 공식 문서는 맥락 크기가 비용을 정하고, 스킬 본문은 실린 뒤 매 호출 다시 읽히며, 포크는 대화 기록을 보지 못한다고 적는다. 아래가 그 원문이다.
- 비용: "Token costs scale with context size … Stale context wastes tokens on every subsequent message."
- 비용: "Delegate these to subagents so the verbose output stays in the subagent's context while only a summary returns to your main conversation."
- 스킬: "Once a skill loads, its content stays in context across turns, so every line is a recurring token cost."
- 스킬, 압축 뒤: "keeping the first 5,000 tokens of each"
- 스킬, context: fork: "The subagent doesn't see your conversation history"
- 스킬, disable-model-invocation: true: "Description not in context, full skill loads when invoked"
- 한계: 문서는 바뀐다. 근거로 다시 쓸 때는 원문을 다시 확인한다.
