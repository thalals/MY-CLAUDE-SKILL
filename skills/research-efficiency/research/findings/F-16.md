# F-16 닫기 전 검증 단계가 있는 사본은 심어 둔 결함을 고치고 닫았고, 없는 사본은 보고만 하거나 두고 닫았다
- 상태: 유효
- 갈래: 연구실
- 세기: 통제 비교 (같은 결함을 심은 사본 두 개에서 한 번씩, Sonnet 5.5)
- 확인: 2026-11-18
- 근거: 선행 없음 (`find` 로 찾은 말: 검증, 닫기). evals/scenarios.md 의 S3 와 돌린 기록(2026-11-17). 두 사본 모두 F-11 의 상태를 틀림으로 바꾸고 본문의 `find` 를 `search` 로 바꿨다. 대조 사본(세션 6e53e5fd, 닫기 전 검증 단계가 없는 판)은 닫은 뒤 `lint` → R2 1건, 본문의 `search` 4줄이 남았다. 새 단계 사본(세션 2790a889)은 닫은 뒤 `lint` → R2 0건 · R11 0건, 본문의 `search` 0줄이다. `total --session 6e53e5fd` → 호출 37 · 누적 입력 4,317,174 · 기준 단가 환산 $3.72. `total --session 2790a889` → 호출 60 · 누적 입력 10,719,897 · 기준 단가 환산 $8.54.
- 사실: 닫기 전에 방향, 기록, 이 스킬을 검증하는 단계가 있는 사본은 틀린 사실에 기댄 방향 두 개와 종합 문장 하나, 본문과 도구가 어긋난 명령과 폴더 이름을 모두 고치고 닫았다. 심지 않은 도구 결함(`set` 이 따옴표 없는 두 단어 라벨을 잘라 엉뚱한 줄을 더함)도 찾아 고쳤다. 단계가 없는 사본은 어긋남을 보고만 하고 고치는 것은 사용자가 정할 일이라며 두었고, 종합 문장은 종합 회차로 미뤘으며, 방향은 그대로 두었다.
- 한계: 한 번씩이다. 결함은 심은 것이라 실제 회차에서 얼마나 생기는지 모른다. 두 세션이 한 일의 양이 달라(새 단계 사본은 측정 명령 하나를 도구에 더했다) 값 차이를 이 단계 탓으로 볼 수 없다. 새 단계 사본은 사용 한도로 세 번 멈췄다 이어져 캐시를 다시 썼다. 대조 사본의 도구에는 R11 점검이 없어 방향의 결함이 보이지 않았다.
- 다시 볼 때: 실제 회차 다섯 번이 이 단계로 닫히면(종합 회차) 회차 기록의 learned 에서 고친 것의 수를 세고, 이 단계에 든 호출을 잰다.
