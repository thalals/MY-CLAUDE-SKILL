# F-06 새 맥락의 서브에이전트도 작게 머물지 않는다
- 상태: 유효
- 갈래: 절차
- 세기: 관측 반복 (평가 시나리오 1번, 포크 27번, 실제 기록의 record 서브에이전트 16번)
- 확인: 2026-11-26
- 근거: 평가 시나리오 A(계획만 세우는 시험, Sonnet 5.5) 는 호출 38, 맥락 42,775 → 272,994, 누적 입력 5,793,808, 출력 154,128 중 생각 130,602. `stats --skill collect-feedback` → 27번 모두 포크 실행, 호출 중앙값 18, 누적 입력 중앙값 1,653,339, 기준 단가 환산 중앙값 $1.57.
- 근거 2: 실제 기록. `stats --skill record-obsidian --since "2026-11-16 17:25" --not-session dec8375b f8e36187 --not-run "2026-11-18 11:51"` → 16번, 서브 호출 중앙값 65(최소 29, 최대 127), 서브 누적 입력 중앙값 13,048,085, 서브 출력 중앙값 62,020. `runs --days 9` 의 11-26 두 실행은 서브에이전트가 맥락 50,791, 50,010 에서 시작해 최대 223,129, 313,213 까지 컸다(F-17).
- 사실: 서브에이전트는 약 43,000~51,000 토큰에서 시작해 읽는 만큼 커진다. 캐시 쓰기는 5분 수명(입력 단가의 1.25배)이다. 출력의 대부분이 생각 토큰일 수 있다.
- 한계: 근거 1 의 시나리오는 실제 기록이 아니다. 근거 2 는 실제 기록이지만 실행마다 주제와 읽은 노트 수가 다르다.
- 다시 볼 때: 서브에이전트의 모델이나 effort 를 바꿀 때(D-02), 하니스가 서브에이전트 시작 맥락(도구 정의, 지시)을 바꿀 때
