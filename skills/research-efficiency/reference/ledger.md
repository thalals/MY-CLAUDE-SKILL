# 장부 형식과 규칙

> 항목을 쓰거나 고치기 전에 읽는다. 도구(`scripts/lab.py`)가 이 형식을 읽으므로 라벨 이름이나 상태 말을 바꾸면 도구도 같은 편집에서 고친다.

## 공통

- 항목 하나가 파일 하나다. 첫 줄은 `# 번호 제목`(시도는 `# 번호 날짜 제목`)이고 그 아래는 `- 라벨: 값` 줄이다. 한 라벨의 값은 한 줄에 쓴다.
- 만들 때는 `new F|D|A --title 제목` 으로 번호와 뼈대를 받는다. 번호를 손으로 정하지 않는다.
- 상태, 우선, 확인처럼 짧은 값은 `set 번호 라벨 값` 으로 고친다. 긴 줄은 파일에서 그 줄만 고친다.
- 다른 항목은 번호로 가리킨다(F-03, D-01, A-01). 도구가 번호를 따라 '인용한 곳' 을 만든다. 장부에 없는 번호는 차단(E5)이다.
- 갈래는 맥락, 지시, 절차, 효과, 측정, 연구실 가운데 하나다(스킬 본문 '연구 대상').
- 숫자는 도구 출력에서 나온 값만 쓰고, 곱하거나 나눈 값은 식을 함께 적는다. 근거에는 다시 낼 수 있는 명령을 적는다. 세션 원본은 30일 뒤 지워지므로(F-13) 명령만 적지 않고 값도 적는다.
- 도구가 내지 못하는 값은 임시 스크립트로 잴 수 있다. 그때는 근거에 도구 밖에서 냈다는 것과 계산식을 적고, 다시 쓸 측정이면 같은 회차에 도구의 명령으로 옮긴다. 장부 밖의 스크립트에만 있는 계산은 다음 회차가 다시 낼 수 없다.
- 대화 내용, 명령 설명, 비밀값은 옮기지 않는다.

## 사실 (`findings/F-번호.md`)

재서 확인한 것만 둔다. 짐작과 아직 재지 않은 것은 방향에 둔다.

| 라벨 | 값 |
|---|---|
| 상태 | 유효, 낡음(조건이 바뀌어 다시 재야 한다), 대체됨(뒤에 → 번호), 틀림(뒤에 까닭) |
| 갈래 | 공통의 여섯 가운데 하나 |
| 세기 | 문서, 관측 1회, 관측 반복, 전후 비교, 통제 비교 가운데 하나로 시작하고 괄호에 횟수와 조건 |
| 확인 | 마지막으로 확인한 날짜. 괄호에 출처를 적을 수 있다 |
| 근거 | 명령과 그 값. 여럿이면 근거 1, 근거 2 |
| 사실 | 근거에서 나오는 문장 |
| 한계 | 이 사실이 말하지 못하는 것 |
| 다시 볼 때 | 어떤 일이 생기면 다시 재야 하는가 |
| 정정 | 있을 때만. 틀렸던 것과 고친 날 |

그 밖의 라벨(원문, 스킬별 줄 등)은 필요하면 더한다.

고치는 규칙
- 다시 재서 같으면 확인 날짜만 고친다. 더 여러 번 재서 굳어졌으면 근거에 더하고 세기를 올린다.
- 일부가 틀렸으면 사실 문장을 고치고 정정 줄에 틀렸던 것을 남긴다.
- 조건이 바뀌어 지금도 맞는지 모르면 낡음으로 바꾼다. 다시 재면 유효로 돌리거나, 새 사실을 쓰고 대체됨으로 바꾼다.
- 통째로 틀렸으면 틀림으로 바꾸고 까닭을 적는다. 지우지 않는다.
- 상태를 바꾸면 그 사실을 인용한 종합의 문장도 같은 회차에 고친다(R2).

## 방향 (`directions/D-번호.md`)

| 라벨 | 값 |
|---|---|
| 상태 | 먼저 잰다(예상을 아직 댈 수 없다), 후보, 시도 중(뒤에 A-번호), 채택, 기각, 완료(물음에 답했거나 끝났다고 볼 기준을 채웠다), 보류. 괄호에 날짜 |
| 갈래 | 공통의 여섯 가운데 하나 |
| 우선 | 숫자. 작을수록 먼저. 사용자가 정한다. 없으면 줄을 쓰지 않는다 |
| 대상 | 무엇을 바꾸거나 재는가 |
| 근거 | 선행 사실·시도의 번호와 값. 없으면 '선행 없음' 과 `find` 로 찾아본 말 |
| 방법 | 어떻게 바꾸거나 재는가 |
| 예상 | 토큰과 기준 단가 환산. 후보가 되려면 있어야 한다 |
| 틀렸다고 볼 기준 | 필요한 횟수와 합격 폭, 볼 명령. 후보가 되려면 있어야 한다. 측정을 넓히는 방향은 '끝났다고 볼 기준' |
| 품질 위험, 드는 것 | 있을 때 |
| 결과 | 채택, 기각, 완료로 닫을 때. 잰 값과 까닭, 나온 사실 번호 |

- 먼저 잰다: 재서 예상과 기준을 채우면 후보로 올리고, 잰 이득이 작으면 기각한다. 재는 것 자체가 목적이었고 답을 얻었으면 완료로 닫고, 결과에 답과 거기서 나온 사실·방향 번호를 적는다.
- 후보: 사용자가 고르면 시도를 만들고 시도 중으로 바꾼다.
- 시도 중: 시도가 채택되면 채택, 실패하면 기각하거나 방법을 바꿔 후보로 돌린다.
- 보류: 지금 하지 않기로 한 것이다. 까닭을 상태 줄에 적는다.

## 시도 (`attempts/A-번호.md`)

| 라벨 | 값 |
|---|---|
| 상태 | 측정 대기, 채택, 실패. 괄호에 날짜. 횟수가 모자라면 측정 대기로 둔다 |
| 갈래 | 공통의 여섯 가운데 하나 |
| 방향 | D-번호와 근거 사실 |
| 대상 스킬 | runs.tsv 의 skill 값 그대로 |
| 바꾼 때 | `YYYY-MM-DD HH:MM`. 이 시각부터의 실행을 바꾼 뒤로 센다 |
| 필요 횟수 | 숫자만 |
| 사전 기준 | 바꾸기 전 기준 단가 환산 중앙값. 숫자만 |
| 바꾼 것 | 파일과 커밋 |
| 사전 측정 | 명령과 값 |
| 예측 | 숫자로. 종합의 어느 문장에서 나왔는지 번호 |
| 틀렸다고 볼 기준 | 채택, 실패, 더 재기를 가르는 값 |
| 품질 확인 | 방법. 실행마다 '품질 확인 1', '품질 확인 2' 줄을 더한다 |
| 겹친 변경 | 같은 때에 바뀐 다른 것 |
| 해석 | 지금까지의 실행을 한 줄로. 잴 때마다 고쳐 쓴다 |
| 예측 평가 | 판정할 때. '맞음' 이나 '빗나감' 으로 시작하고 까닭 |
| 결론 | 판정할 때 |

- 대상 스킬, 바꾼 때, 필요 횟수, 사전 기준은 도구가 읽는다. `status` 가 runs.tsv 에서 바꾼 뒤 실행 수와 중앙값을 낸다. 실행마다의 숫자를 항목에 옮겨 적지 않는다. 자세한 값은 `stats --skill 대상 --since "바꾼 때"` 로 본다.
- 스킬 실행이 아닌 것을 바꾼 시도(늘 실리는 맥락 등)는 대상 스킬에 '없음' 을 적고, 볼 명령을 틀렸다고 볼 기준에 적는다.
- 채택한 시도는 `status` 의 감시에 계속 나온다. 채택 뒤 중앙값이 다시 올라가면 그 회차의 초점으로 삼는다.

## 종합 (`knowledge.md`)

- 지금 아는 것을 절로 나눠 적는다: 값이 정해지는 법, 반복 절차, 늘 실리는 맥락과 지시, 재는 법, 통하지 않은 것과 빗나간 예측, 아직 모르는 것.
- `- ` 로 시작하는 문장마다 근거 번호를 단다. 번호가 없으면 차단(E8)이다. reference 의 정의에 기대는 문장에는 metrics.md 를 적는다.
- 80줄 이내다(R1). 새 문장을 넣을 때 겹치는 문장을 합치고 세부 수치는 사실 파일에 둔다.
- 판정이 끝나지 않은 수치는 쓰지 않는다. 진행은 `status` 가 낸다.
- 고치면 머리말의 '마지막으로 고친 회차' 를 고친다.

## 회차 기록 (`log.tsv`)

`close` 가 쓴다. 손으로 고치지 않는다. 열은 n(회차 번호), start_kst, end_kst, session, kind(구축, 측정, 판정, 탐색, 적용, 종합), focus, ids, did, learned, next, calls, sub_calls, cum_in, out, usd, ref_usd 다.

- `close` 와 `runs --save` 는 잠금을 잡고 읽은 뒤 파일을 통째로 바꿔 쓴다. 같은 때에 열린 두 회차(2026-11-26 에 두 번 있었다)가 같은 회차 번호를 받거나 서로의 줄을 지우지 않게 하려는 것이다.

- 든 값은 그 세션에서 회차를 시작한 때(스킬을 부른 때)부터 닫은 때까지의 본 대화와 서브에이전트 호출을 더한 것이다. 닫은 뒤의 호출은 들어가지 않는다. 같은 회차를 다시 닫으면 그 줄을 고쳐 쓴다.
- next 는 다음 회차가 `status` 에서 가장 먼저 보는 인계다. 누가 읽어도 바로 시작할 수 있게 번호와 명령으로 적는다.
- learned 는 닫기 전에 검증한 답이다(스킬 본문 '회차' 의 '검증하고 발전시킨다' 단계). `close` 가 `--check-directions`, `--check-records`, `--check-skill` 을 '방향: … / 기록: … / 스킬: …' 로 이어 적는다. 종류가 측정이 아니면 셋이 다 있어야 닫힌다. 종합 회차가 모아서 되풀이된 것을 고친다. 3회차까지는 연구하는 법에서 배운 것을 자유롭게 적었다.

## 목록 (`index.md`)

도구가 쓴다. 한 줄은 번호 · 상태 · 갈래 · 날짜 · 제목 · 인용한 곳이다. 도구 없이 장부를 볼 때의 입구다.

## 점검 (`lint`)

| 번호 | 뜻 | 고치는 법 |
|---|---|---|
| E1 | 첫 줄이 형식과 다르거나 번호가 파일 이름과 다르다 | 첫 줄을 고친다 |
| E2 | 필수 라벨이 없거나 값이 비었다 | 채운다 |
| E3 | 상태 말이 어휘에 없다 | 위 표의 말로 시작하게 고친다 |
| E4 | 갈래나 세기 말이 어휘에 없다 | 위 표의 말로 고친다 |
| E5 | 장부에 없는 번호를 가리킨다 | 번호를 고치거나 그 항목을 만든다 |
| E6 | 시도의 바꾼 때, 필요 횟수, 사전 기준이 형식과 다르다 | 형식대로 고친다 |
| E7 | 후보인 방향에 기준이 없다 | 기준을 쓰거나 먼저 잰다로 내린다 |
| E8 | 종합이 없거나 근거 번호 없는 문장이 있다 | 번호를 달거나 문장을 뺀다 |
| R1 | 종합이 80줄을 넘는다 | 합치고 세부를 사실로 내린다 |
| R2 | 종합이 유효하지 않은 사실을 인용한다 | 그 문장을 고친다 |
| R3 | 유효한 사실을 아무도 인용하지 않는다 | 종합에 넣거나 그대로 둔다 |
| R4 | 확인한 지 60일 넘은 유효 사실 | 다시 재거나 낡음으로 바꾼다 |
| R5 | 열린 방향이 15개를 넘는다 | 보류나 기각으로 닫는다 |
| R6 | 닫은 방향(채택, 기각, 완료)에 결과가, 판정한 시도에 결론이나 예측 평가가 없다 | 적는다 |
| R7 | 방향의 근거에 번호도 '선행 없음' 도 없다 | 선행 번호를 달거나 '선행 없음' 과 찾아본 말을 적는다 |
| R8 | 목록이 장부와 다르다 | `index` 나 `close` |
| R9 | runs.tsv 에 진행 중으로 적힌 줄이 있다 | 끝난 뒤 `runs --save` |
| R10 | 지난 회차가 다음에 할 일을 남기지 않았다 | 다음에 닫을 때 적는다 |
| R11 | 열린 방향이나 판정 대기 시도가 유효하지 않은 사실을 근거로 든다 | 근거를 다시 확인해 고치거나 보류, 기각으로 닫는다 |

차단(E)은 닫기 전에 고친다. 보고(R)는 닫는 것을 막지 않는다. R2 와 R11 은 회차의 '검증하고 발전시킨다' 단계에서, 나머지는 종합 회차에서 정리한다.
