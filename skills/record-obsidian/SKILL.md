# record-obsidian

대화를 Obsidian 볼트에 남기는 순서다. 본 대화는 daily 와 넘김 글만 쓰고, record 갱신은 새 맥락의 서브에이전트 하나가 한다. 형식과 세부 규칙은 볼트의 규칙 파일에 있다.

- 볼트는 `/Users/hyeongminpark/Library/Mobile Documents/iCloud~md~obsidian/Documents/Obsidian` 이다(공백이 있어 따옴표로 감싼다). 저장소 경로는 전역 CLAUDE.md '시스템 사전' 에 있다.
- `<스킬>` 은 이 스킬을 불러올 때 알려 주는 'Base directory' 다. 서브에이전트에게는 절대 경로로 풀어 준다.

## 원칙

- daily history 는 경위, record 는 지금 참인 사실, proposals 는 아직 정하지 않은 구조·규칙·스킬 변경 제안이다.
- 동작 사실은 대화가 아니라 origin/develop 코드에서 읽고, 그 대조는 서브에이전트가 한다. 시각·커밋 값은 도구 출력에서만 가져오고, 어느 주제인지 같은 의미 판단은 내가 한다.
- 호출 한 번이 그때까지의 대화 전체를 다시 읽는다(11-16 실측: 기록 한 번에 호출 43번 × 평균 24만 토큰). 그래서 본 대화에서는 호출을 줄인다.
  - 독립된 읽기와 편집은 한 메시지에 함께 보낸다.
  - 호출이 많은 record 갱신은 규칙과 노트만으로 시작하는 서브에이전트에 맡긴다.
- 폴더·노트 종류·시스템 구성, 규칙 파일, 이 스킬은 사용자가 확인한 제안으로만 바꾼다(`<스킬>/reference/proposals.md`).

## 지키는 것

- 저장소는 읽기만 한다(`git fetch`, `log`, `show`, `merge-base`). 커밋, 브랜치 이동, push 는 하지 않는다.
- 볼트 파일은 쓰기 직전에 다시 읽고, 읽은 뒤 바뀌었으면(다른 세션의 기록 등) 합쳐서 쓴다.
- env/*, *.env, *private* 파일은 열지 않는다. 비밀값, URL, 호스트명은 쓰지 않는다.

## 1. 한 번에 읽고 시작한다

`python3 "<스킬>/scripts/start.py"` 를 돌린다. 기록할 세션이 지금 세션이 아니면(Codex, 다른 Claude 세션) `--session <세션 ID 또는 jsonl 경로>` 를 준다. 한 번의 출력에 오늘 날짜·시각(KST), `daily history/SKILL.md` 전문, 열린 제안과 '마지막 전체 검진', 오늘 날짜 노트의 frontmatter 와 주제(H2) 목록, 이 세션의 기록된 범위와 그 뒤 타임라인이 있다. 규칙은 매 실행 이 출력으로 새로 읽고, 기억이나 예전 요약으로 대신하지 않는다.

본 대화는 record 를 읽지 않는다. `record/SKILL.md`, 시스템 지도, 노트, 볼트 루트 `index-guide.md` 는 서브에이전트가 읽는다. 사용자가 정한 제안을 반영하느라 규칙 파일을 고칠 때만 그 파일의 고칠 줄을 읽는다.

## 2. daily 를 쓴다

daily SKILL 의 '절차' 1~7 을 따른다. 8(record 갱신)은 4단계의 서브에이전트가 하고, 9(확인 목록)는 5단계에서 본다.
- 시각은 도구 출력(start.py 의 날짜·타임라인, `git log`)에서만 가져온다. 세션 원본이 없으면 그 자리에 `MM-DD 미확인` 을 쓰고, 사용자가 알려 준 시각이 있으면 보고에서 그 시각을 써도 되는지 묻는다. 기록하는 지금보다 늦은 시각은 쓰지 않는다. 커밋·머지 시각은 `TZ=Asia/Seoul git log --date=format-local:'%m-%d %H:%M'` 로 뽑는다.
- 결과·상태(커밋, 머지, 티켓 상태)는 daily SKILL 절차 4 대로 git log·Jira 로 확인한다. 코드는 다시 읽지 않는다.
- 오늘 파일이 있으면 병합한다. 같은 티켓, 같은 저장소·목적은 기존 주제에 넣고 애매하면 새 주제로 둔다. 같은 질문이나 결정을 다시 다뤘으면 기존 문단과 주제 설명의 결과·상태 문장을 최신으로 고치고, 앞선 결과·상태는 작업 내용에 경위로 남긴다.
- 오늘 파일은 start.py 의 주제 목록으로 병합할 주제를 고르고 그 주제 절만 읽는다(108KB 날짜 노트도 있다). 새 주제만 더할 때는 본문을 다 읽지 않는다.
- 지난 날짜 파일은 고치지 않고 `이전 기록:` 링크로 잇는다.
- 'record 도 다 최신으로', '사전 최신으로 맞춰줘' 처럼 record 전체를 말하면 record 전체 최신화다. 다른 대화와 함께 왔어도 그 작업을 오늘 노트에 따로 주제 하나로 쓴다.
- 목차, sessions, 두 가이드(index-guide, date-guide) 편집은 본문 편집과 같은 메시지에 보낸다.
- 대화에서 사용자가 열린 제안을 정했는데 아직 반영하지 않았으면 이때 `reference/proposals.md` 대로 반영한다. record 노트를 고쳐야 하는 부분만 넘김 글에 넣는다.

## 3. 넘김 글을 쓴다

이번에 쓰거나 고친 주제(H2)마다 대화에서 아래를 뽑는다. 서브에이전트는 대화를 보지 못하므로 판단을 가른 사용자 말은 원문과 시각으로 넣는다.
- 범위 열쇠: 시스템, 패키지 키, 한국어 이름, 엔티티. 대화에 나온 코드 이름(패키지, 클래스)으로 쓰고, 노트 이름에 맞추는 일은 서브에이전트가 한다.
- 지점 열쇠: 티켓 키, METHOD 경로, 토픽, 클래스·메서드, env 키 이름, 에러 키, 정책 이름
- 사실과 갈래. 갈래는 코드 사실, 사용자가 정한 업무 규칙(정책), 사용자가 의도라고 한 제약(예외 사항), 고치기로 한 문제(보완 사항), 정하지 않은 것(확인 사항), 대상 아님(작업 환경, 스타일, 도구) 가운데 하나다.
  - 근거는 `<저장소> origin/develop <sha>` 의 파일이나 그 동작을 넣은 커밋, 또는 사용자 발언 `MM-DD HH:MM "짧은 원문"`(시각을 모르면 `MM-DD 미확인`)이다.
  - 정책은 시스템의 업무 규칙이다. 볼트·스킬·기록 규칙에 관한 결정은 대상 아님(도구)이다.
  - 에이전트 수정안을 "작업해" 처럼 승인한 것은 구현 승인이고, "기록해" 같은 말은 지시다. 둘 다 정책이 아니라고 적는다.
  - 대화 중에 지난 추정이나 열린 제안을 다시 확인했으면 그 노트·제안과 확인한 내용을 적는다. 기록하려고 record 를 따로 찾지는 않는다(서브에이전트가 찾는다).
- 상태: 커밋·머지·티켓 상태와 확인 결과. 사용자가 말한 것과 git 이 다르면 둘 다 적는다.

넘김 글 형식:

```
- 볼트: <경로> | 오늘: YYYY-MM-DD | 날짜 노트: daily history/YYYY/MM/YYYY-MM-DD.md
- 요청: 기록 (또는 record 전체 최신화 n/m <시스템>, 볼트 전체 검진)
- 주제: [[daily history/YYYY/MM/YYYY-MM-DD#<제목>]]
  - 범위 열쇠: … | 지점 열쇠: …
  - 사실: <갈래> · <한 줄> · 근거: …
  - 사용자 판단: <정책·예외·보완으로 정한 말과 시각, 구현 승인·지시 표시>
  - 상태: <커밋·머지·티켓 상태와 확인 결과>
```

주제가 모두 대상 아님이면 서브에이전트를 띄우지 않는다. 날짜 노트 frontmatter `record` 에 주제마다 `"<주제 제목> · 대상 아님 · <사유>"` 를 쓰고 `python3 "<볼트>/record/record-lint.py"` 를 돌려 차단을 0 으로 만든 뒤 5단계로 간다.

## 4. record 를 서브에이전트에 맡긴다

Agent 도구로 general-purpose 서브에이전트 하나를 띄운다. 대화 fork 가 아니라 새 맥락이어야 호출이 싸다. 프롬프트는 이 순서로 쓴다.
1. "record-obsidian 의 record 갱신을 맡는다. 먼저 `<스킬>/reference/record-run.md` 를 읽고 그대로 따른다." (`<스킬>` 은 절대 경로로 쓴다)
2. 읽을 스타일 주제 파일: 전역 CLAUDE.md 스타일 폴더의 `work/docs-record.md`
3. "넘김 글:" 뒤에 넘김 글

- 서브에이전트가 끝날 때까지 볼트 파일을 고치지 않는다. 결과를 미리 짐작해 보고하지 않고 알림을 기다린다.
- 서브에이전트가 물을 것으로 돌려준 것은 보고에서 사용자에게 묻는다.
- record 전체 최신화는 노트가 있는 시스템마다 서브에이전트 하나씩 차례로 맡긴다. 요청 줄에 몇 번째인지(n/m)와 시스템을 적고, 앞 보고를 다음 넘김 글에 붙인다.
- Agent 도구를 쓸 수 없으면 `reference/record-run.md` 를 직접 따른다.

## 5. 보고한다

먼저 daily SKILL 확인 목록을 본다. 이번 주제가 daily index-guide 의 시스템·도메인 줄과 date-guide 의 날짜 줄에 들어갔는지도 본다(lint 는 보지 않는다). 서브에이전트 결과로 주제 설명의 결과·상태 문장이 달라졌으면(전체 최신화 주제 등) 그 문장을 고친다.

표 하나에 단계마다 고친 파일과 한 일을 적는다. record·지도·검진·lint 줄은 서브에이전트 보고에서 옮긴다. 서브에이전트를 띄우지 않았으면 lint 줄은 본 대화의 lint 결과로 쓰고 나머지는 '해당 없음' 이다.
- daily: 주제, 병합인지 추가인지
- record: 노트, 연산, basis 변화
- 지도: 고친 aliases·keywords·지도 머리와 이유, 나눈 노트. 고치지 않았으면 그 이유
- 검진: 여섯 가지 점검에서 찾은 것과 처리
- lint: 차단 수, 보고 R1~R10

표 아래에는 이것을 적는다.
- 정리한 제안: 맞춘 제안과, 반영하거나 거절해 proposals 에서 지운 제안마다 한 줄(어디의 무슨 제안, 다시 확인한 결과를 쓴 곳, 제안과 달랐던 점). 없으면 '없음'
- 서술과 다름, 확인하지 못한 결과, 보류, 다 보지 못한 커밋, 판단이 필요한 확인 사항
- 열린 제안: `proposals.md` 에서 상태가 제안인 것을 한 줄씩. 이번에 새로 올렸거나 근거를 더한 것을 표시한다
- '마지막 전체 검진' 이 없거나 7일보다 오래됐으면 전체 검진을 할지 묻는다

## 빨간 신호

- "record 도 내가 바로 고치면 빠르다" → 본 대화의 호출은 대화 전체를 다시 읽는다. record 는 서브에이전트에 맡긴다.
- "규칙은 지난번에 읽었다" → start.py 출력으로 새로 읽는다.
- "넘김 글은 짧게 요약하면 된다" → 서브에이전트는 대화를 못 본다. 판단을 가른 사용자 말과 시각, 갈래, 상태를 넣는다.
- "제안은 대화에서 말했으니 됐다" → `proposals.md` 에 남겨야 다음 세션도 이어서 묻는다.
