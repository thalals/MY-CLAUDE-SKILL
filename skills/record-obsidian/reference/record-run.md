# record 갱신 실행 (서브에이전트)

본 대화가 넘긴 넘김 글로 record 를 고치는 절차다. 대화 원문은 보지 못한다. 근거는 넘김 글, 날짜 노트의 그 주제 절, origin/develop 코드뿐이다. 넘김 글이나 daily 서술이 코드와 다르면 코드를 쓰고 보고의 '서술과 다름' 에 적는다. `<스킬>` 은 이 파일이 든 `reference/` 의 상위 폴더다.

## 시작

한 메시지에서 함께 읽는다.
- `<볼트>/record/SKILL.md` 전문. 규칙은 매번 새로 읽고 기억으로 대신하지 않는다.
- 넘김 글 범위 열쇠의 시스템 지도 `record/<조직>/<시스템>/index-guide.md`
- 날짜 노트에서 넘김 글 주제의 절. `grep -n '^## '` 로 위치를 찾아 그 범위만 읽는다.
- 볼트 루트 `proposals.md`
- 프롬프트에 적힌 스타일 주제 파일

원칙
- daily 주제와 record 노트는 서로를 가리킨다. record 를 고친 주제는 처리 기록으로 그 노트를 가리키고, 대화에서 가져온 사실을 받은 노트는 `sources` 로 그 주제를 가리킨다.
- 어느 노트가 자리인지, 같은 사실인지, 정책인지 같은 의미 판단은 지도와 규칙을 읽고 내가 한다. 커밋·링크 대조 값은 도구 출력을 쓴다. 도구 출력과 기억이 다르면 도구를 따른다.
- 폴더·노트 종류·시스템 구성과 규칙은 사용자가 확인한 제안으로만 바꾼다. 제안은 `<스킬>/reference/proposals.md` 대로 올린다.

## 아끼는 법

호출마다 그때까지 읽은 것을 모두 다시 읽는다. 앞에서 읽은 큰 출력은 남은 호출마다 다시 값을 낸다.
- 독립된 읽기와 명령은 한 메시지나 한 번의 Bash 로 묶는다.
- 노트는 통째로 읽지 않는다. `grep -n '^## '` 로 절 위치를 보고 고칠 절만 읽는다(Read 의 offset·limit, 또는 `sed -n`).
- `git show` 는 `--stat` 로 바뀐 파일을 먼저 보고 필요한 경로만 연다. 긴 출력은 grep·head 로 줄인다.

## 도구

- `visit.py` (`<볼트>/record/visit.py`): 열쇠가 적힌 노트 줄·daily, 후보 노트별 basis 이후 커밋, 여러 노트에 걸린 커밋을 낸다. `--lines` 는 줄을 자르지 않고 `[절 > 부모 줄]` 을 붙인다. `--package`, `--fetch`, `--files`, `--all`. 쓰는 법은 파일 머리말에 있다.
- `record-lint.py` (`<볼트>/record/record-lint.py`): 먼저 `build-index.py` 로 시스템 지도의 노트 목록과 노트 머리 `> 절:` 줄을 다시 만든 뒤 차단 C1~C10, 보고 R1~R10, 저장소별 마지막 fetch 를 낸다. `--check` 는 다시 만들지 않고 낡았는지만 본다.

## 1. 시스템 지도에서 방문 노트를 고른다

record 의 지도는 시스템마다 한 장이다. 시스템 지도의 '노트' 절에 그 시스템의 모든 노트가 폴더별로 있고(`build-index.py` 가 노트에서 만든다), 노트마다 크기·마지막 대조일·찾는 말·절 이름·정책 이름이 있다. 끝의 '패키지별' 줄이 한 패키지의 기능·상태·계약·정책 노트를 묶는다. 하위 폴더에는 지도가 없다.

1. 범위 열쇠의 시스템 지도 머리의 '어디로 가나' 로 노트 종류를 고르고, '노트' 절에서 찾는 말·절 이름이 맞는 노트를 후보에 넣는다. 패키지가 정해지면 '패키지별' 줄의 노트를 모두 후보에 넣는다. 한 사실의 상태, 정책, 흐름, 계약은 서로 다른 폴더에 나뉘어 있다.
2. `visit.py <지점 열쇠…> --package <패키지>` 로 열쇠가 적힌 노트를 더한다. '없음' 으로 나온 열쇠는 4단계의 자리 없는 개념으로 넘긴다.
3. 방문 목록을 적는다.
   - 방문 목록은 이번 주제의 사실이 들어갈 노트와, 같은 지점 열쇠가 이미 적힌 노트다.
   - 방문 목록을 고르는 지점 열쇠는 티켓 키·클래스·경로처럼 좁은 것만 쓴다. 토픽·이벤트 이름 같은 넓은 말은 4단계 `--lines` 모순 점검에만 쓴다.
   - 열쇠가 frontmatter `sources` 나 본문의 daily 출처 링크(주제 제목)에만 있는 노트, `## 관련`·`## 변경 이력` 줄에만 있는 노트는 방문 목록이 아니다. 그런 노트는 4단계 `--lines` 모순 점검에서만 본다.
   - 2단계는 이 노트들을 고치고, 4단계는 이 노트들을 검진한다.
4. 갈 곳이 없을 때는 이렇게 한다.
   - 시스템 지도에 노트가 없다고 적혀 있으면(설계 전) 그 시스템 내부 사실은 보류한다. 다른 시스템 노트의 상대 쪽 줄에 들어갈 계약 사실은 그 노트에서 처리한다. 그 시스템에 보류가 쌓이면 구조 제안의 '왜' 에 근거를 더한다.
   - 설계된 시스템인데 맞는 노트가 없으면, 그 시스템 '이 폴더의 목적' 노트의 배치 규칙으로 지금 있는 폴더와 노트 종류 안에서 정본 노트를 정한다.
   - 맞는 폴더나 노트 종류가 없으면 구조 제안을 올리고, 그 사실은 확인을 받을 때까지 보류한다.

## 2. 잎에서 upsert 한다

방문 목록의 노트마다 `record/SKILL.md` 의 '갱신 절차' 를 따른다. 거기에 아래 네 가지를 더한다.

- 지난 제안 맞추기: 쓰기 전에, 이번 주제와 맞는 제안이 이미 남아 있는지 찾는다. 제안은 에이전트가 앞서 남긴 추정과 물음이다.
  - 찾는 곳: 방문 노트의 `## 확인 사항` 줄(추정, 의도 미확인, 운영 확인, 정책 후보), daily frontmatter `record` 의 확인 대기·보류·중단 줄(`grep` 으로 열쇠를 찾는다), `proposals.md` 에서 상태가 제안인 항목. 노트 쪽은 `visit.py <열쇠…> --lines` 출력에서 고른다.
  - 맞는 제안이 있으면 그 문장을 근거로 쓰지 않는다. 넘김 글의 대화 근거와 origin/develop 코드로 다시 확인한 것만 쓴다.
  - 코드 줄에서 바로 읽히는 동작은 코드 사실로 옮긴다. 여러 지점을 이어 추론했고 실행해야 정해지는 부분(예외 종류, 외부 응답, 실행 순서)만 `추정:` 으로 남긴다.
  - 확인한 내용은 제자리에 쓰고 제안은 없앤다. 코드 사실은 본문, 사용자가 정한 규칙은 정책, 의도라고 한 것은 예외 사항, 고치기로 한 것은 보완 사항이다. 확인 사항 줄은 지운다. 지난 daily 의 확인 대기·보류·중단 줄은 고치지 않고 이번 주제 처리 기록 끝에 `· 정리: <날짜> <주제>` 로 잇는다. proposals 항목은 반영하거나 거절하면 그 편집에서 지운다.
  - 다시 확인한 결과가 제안과 다르면 그 차이를 보고에 적는다. 이번 근거로도 정할 수 없는 부분만 지금 근거로 고쳐 쓴 확인 사항 한 줄로 남기고 보고의 물을 것에 적는다.
  - 대화 근거가 origin/develop 에 없어 다시 확인할 수 없으면 그 제안은 그대로 두고, 보고의 정리한 제안에 '다시 확인 못 함' 과 이유를 적는다.
- 최신화
  - `visit.py <지점 열쇠…> --package <패키지> --fetch` 가 방문 노트의 basis 저장소를 fetch 하고 노트별 basis 이후 커밋을 낸다. lint 는 fetch 하지 않는다.
  - 그 커밋을 모두 대조한다. 이번 주제와 무관해 보이는 커밋도 대조한다. 사실이 바뀌었는지는 `--files` 로 바뀐 파일을 보고, 필요한 커밋만 `git show` 로 읽어 판단한다.
  - 반영할 사실을 반영한다. 커밋을 모두 대조했으면 사실 연산이 변경 없음이어도 basis 와 verified 를 올린다. basis 이후 커밋이 0건인 저장소도 develop 끝으로 올린다.
  - paths 밖 커밋이 노트 범위의 사실을 바꾸면 그 경로를 paths 에 더하고 대조한다.
  - 다 보지 못했으면 basis 를 올리지 않고, 남은 커밋을 보고에 적는다.
- 티켓 판정: 넘김 글 상태 줄에서 사용자가 머지를 말했는데 record SKILL 갱신 절차 4 의 grep 에 그 티켓 커밋이 없으면 미반영으로 두고, 물을 것에 머지한 커밋 sha 나 브랜치를 적는다. 스쿼시 메시지에 티켓 키가 없으면 grep 이 놓친다.
- 출처 잇기
  - 노트에 쓴 사실이나 이유를 daily 주제에서 가져왔으면 frontmatter `sources` 에 그 주제 링크를 더한다. 사용자 결정, 의도·제약 확인, 티켓 판정, 대화에서 확인한 코드 사실이 여기에 든다.
  - 커밋 대조로만 고친 노트에는 더하지 않는다. 그 근거는 basis 와 변경 이력이다.
- 넘침: 넣으면 노트가 record SKILL 의 크기 한도(차단)를 넘으면 그 나누는 법대로 같은 폴더에 `<패키지>-<갈래>.md` 로 먼저 나눈 뒤 넣는다. 제안 없이 하고 처리 기록과 보고에 적는다. 크기 때문에 사실을 보류하지 않는다.

## 3. 지도와 찾는 말을 맞춘다

시스템 지도의 노트 목록과 노트 머리의 `> 절:` 줄은 `record-lint.py` 가 노트에서 다시 만든다. 손으로 고치지 않는다.

- 노트를 만들었거나 노트의 범위가 바뀌었으면(새 기능 H2, 새 엔티티, 이름 변경) 그 노트의 요약 인용과 frontmatter `aliases`·`keywords` 를 고친다. 지도에는 이것이 실린다. 확인 사항, 보완 사항, 진행 중에만 있는 말은 올리지 않는다.
- 시스템 지도 머리('어디로 가나', '헷갈리는 말', 상대 시스템)는 손으로 쓴다. 노트 종류의 쓰임이나 상대 시스템이 바뀌었을 때만 고친다.
- 폴더를 만들거나 바꾸면 볼트 루트 `index-guide.md` 의 폴더 줄을 고친다. 폴더 신설은 구조 제안으로 확인을 받은 뒤에만 한다. 같은 폴더에 `<패키지>-<갈래>.md` 로 나누는 것은 폴더를 만들지 않으므로 제안 없이 한다.

## 4. 검진한다

방문 목록에 llm-wiki 점검 여섯 가지(Karpathy)를 한다. 규칙 안에서 고칠 수 있는 것은 고치고, 정할 수 없는 것은 확인 사항이나 보고로, 구조가 맞지 않는 것은 구조 제안으로 보낸다.

- 모순: `visit.py <열쇠…> --lines` 로 같은 열쇠가 나온 줄을 노트끼리 비교한다 → 코드로 정해 대체한다. 못 정하면 확인 사항에 쓴다.
- 낡은 주장: 2단계 표류 대조, 그리고 열쇠가 나온 daily 날짜가 노트 verified 보다 늦은데 노트에 없는 결정 → 반영하거나 확인 사항에 쓴다.
- 고아: 노트는 lint 가 시스템 지도에 싣는다(C1). 풀리지 않는 링크는 lint C2 → 링크를 고친다.
- 자리 없는 개념: `visit.py` 가 '없음' 으로 낸 열쇠, 시스템 지도 '패키지별' 줄에 없는 패키지 → 배치 규칙 안에서 노트를 정한다. 자리가 없으면 구조 제안.
- 빠진 교차 참조: 같은 패키지의 다른 면 노트('패키지별' 줄)가 이 사실을 상대 쪽·관련 줄로 서로 가리키는지 → 잇는다.
- 메울 수 있는 빈칸: 방문 노트의 확인 사항 가운데 지금 코드·커밋으로 답할 수 있는 것(이번 주제와 맞는 것은 2단계 지난 제안 맞추기에서 이미 처리) → 답을 본문에 쓰고 그 줄을 옮긴다. 사용자 판단이 필요하면 보고의 물을 것에 적는다.

매 실행은 방문 목록만 본다.

## 5. 잇고 점검한다

1. 날짜 노트 frontmatter `record` 에 주제마다 처리 결과를 한 줄씩 쓴다. 형식은 `record/SKILL.md` '처리 기록' 에 있다. 방문 노트의 표류를 대조해 고친 노트는 그 주제 줄 끝에 `· 표류 대조: <노트>(<연산>)` 로 덧붙인다. 날짜 노트는 쓰기 직전에 다시 읽는다(본 대화가 방금 썼다).
2. `python3 "<볼트>/record/record-lint.py"` 를 돌린다. 차단이 0 이 될 때까지 고친다.
3. lint 가 보지 않는 것을 점검한다.
   - 고친 노트의 머리 요약과 aliases·keywords 가 지금 내용과 맞다.
   - 새로 생긴 말(기능 이름, 정책 이름, 티켓 키)은 시스템 지도나 `visit.py` 검색으로 찾을 수 있다.

## 6. 돌려줄 보고

마지막 메시지로 본 대화에 돌려준다. 본 대화가 사용자 보고에 옮긴다. 줄마다 짧게 쓴다.
- record: 노트마다 연산과 basis 변화
- 지도: 고친 aliases·keywords·지도 머리와 이유, 나눈 노트. 고치지 않았으면 이유
- 검진: 여섯 가지에서 찾은 것과 처리
- lint: 차단 수, 보고 R1~R10
- 정리한 제안, 서술과 다름, 확인하지 못한 결과, 보류, 다 보지 못한 커밋
- 물을 것: 사용자 판단이 필요한 확인 사항, 정책과 부딪힌 새 정보(지금 정책, 새 정보, 코드 동작, 영향)
- 열린 제안: `proposals.md` 에서 상태가 제안인 것 한 줄씩(이번에 새로 올렸거나 근거를 더한 것 표시)

## 전체 최신화와 전체 검진

- record 전체 최신화를 받았으면 넘김 글의 시스템 범위에서 `visit.py --all --fetch` 의 모든 노트가 방문 목록이다. 여러 노트에 걸린 커밋은 '커밋별 노트' 로 한 번만 읽는다.
- 볼트 전체 검진은 같은 여섯 가지를 모든 노트에 하고, 마치면 `proposals.md` 의 '마지막 전체 검진' 날짜를 고친다. 전체 최신화에서 모든 노트에 여섯 점검을 했으면 그것도 전체 검진이므로 날짜를 고친다.
- 본 대화가 시스템마다 차례로 맡겼으면(넘김 글 요청 줄의 n/m) 맡은 시스템의 노트만 본다. 저마다 lint 를 돌려 차단을 0 으로 만들고, 처리 기록 줄과 '마지막 전체 검진' 날짜는 마지막(m/m) 서브에이전트만 쓴다. 앞 서브에이전트의 보고는 넘김 글에 붙어 온다.
- 여러 에이전트가 동시에 나눠 고칠 때만 `<볼트>/.record-staging/` 에 복사해 고친다(`/tmp` 는 쓰지 않는다). lint 를 통과시킨 뒤 볼트에 반영하고 staging 폴더를 지운다. 반영 직전에 그사이 볼트 파일이 바뀌었는지 비교한다. 차례로 할 때는 쓰지 않는다.

## 지키는 것

- 저장소는 읽기만 한다(`git fetch`, `log`, `show`, `merge-base`). 커밋, 브랜치 이동, push 는 하지 않는다.
- 볼트 파일은 쓰기 직전에 다시 읽고, 읽은 뒤 바뀌었으면(다른 세션의 기록 등) 합쳐서 쓴다.
- env/*, *.env, *private* 파일은 열지 않는다. 비밀값, URL, 호스트명은 쓰지 않는다.
- 사용자에게 직접 묻지 않는다. 물을 것은 보고에 적어 본 대화에 돌려준다.

## 빨간 신호

- "이 표류 커밋은 이번 주제와 무관하다" → 방문한 노트의 표류는 이번 범위다. 대조해서 basis 를 올리거나, 보지 못한 커밋을 보고한다.
- "사실이 그대로니 basis 도 그대로 둔다" → 커밋을 다 대조했으면 basis 를 올린다. 대조했다는 표시다.
- "grep 으로 찾았으니 지도는 안 봐도 된다" → grep 은 이미 적힌 말만 찾는다. 새 사실의 정본과 다른 폴더에 있는 면은 시스템 지도의 '패키지별' 줄에서 보인다.
- "basis·paths 만 고치면 된다" → 대화에서 가져온 사실로 고친 노트에는 `sources` 에 daily 주제 링크도 단다.
- "새 말이 생겼으니 keywords 에 올린다" → keywords 에는 본문 사실의 범위만 올린다. 확인 사항에만 있는 말은 올리지 않는다.
- "지도의 노트 목록을 손으로 고친다" → 노트 목록과 `> 절:` 줄은 lint 가 다시 만든다. 손으로 고치면 다음 lint 가 덮는다.
- "넘칠 것 같으니 사실을 보류한다" → 크기 때문에 보류하지 않는다. 같은 폴더에 나눈 뒤 넣는다.
- "맞는 폴더가 없으니 하나 만든다" → 구조 제안을 올리고 확인을 기다린다. 그동안 그 사실은 보류한다.
- "앞서 쓴 추정이니 그대로 옮기면 된다" → 추정은 근거가 아니다. 넘김 글의 대화 근거와 코드로 다시 확인한 것만 쓴다.
- "본문에 썼으니 확인 사항 줄은 둬도 된다" → 맞춘 제안은 없앤다. 둘 다 남기면 다음 기록이 옛 추정을 아직 열린 물음으로 읽는다.
- "넘김 글에 그렇게 적혀 있다" → 넘김 글은 대화 서술이다. 동작 사실은 origin/develop 코드로 다시 읽는다.
- "사용자가 정책으로 남기라고 했다" → 그 말이 가리킨 설명이 코드와 다르면 정책을 쓰지 않는다. 처리 기록을 확인 대기로 두고 물을 것에 지금 정책·새 정보·코드 동작·영향을 적는다.
- "검진은 lint 가 했다" → lint 는 형식만 본다. 모순, 낡은 주장, 빠진 교차 참조는 4단계에서 내가 본다.
- "노트를 통째로 읽는 게 편하다" → 고칠 절만 읽는다. 큰 노트 하나가 남은 호출마다 다시 읽힌다.
